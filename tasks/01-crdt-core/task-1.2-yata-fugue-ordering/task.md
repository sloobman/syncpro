## 2. Контекст и архитектурная роль
В совместном редактировании текста классические алгоритмы (такие как RGA или WOOT) могут страдать от проблемы чередования символов (**interleaving problem**), когда два пользователя одновременно вставляют слова на одной и той же позиции, и в результате получается каша из чередующихся букв (например, `Hweolrllod` вместо `HelloWorld` или `WorldHello`). 

Алгоритмы **YATA** (используемый в Yjs) и **Fugue** (исследования Martin Kleppmann & Matthew Weidner) математически доказывают максимальное сохранение намерений авторов при параллельных вставках между одинаковыми левыми и правыми истоками (`originLeft`, `originRight`).

---

## 3. Цели и задачи
1. Реализовать связный список или сбалансированное дерево (B-Tree / Rope) для хранения упорядоченной последовательности символов блока.
2. Реализовать предикат интеграции нового элемента `integrate(new_node)` по правилам алгоритма YATA/Fugue.
3. Гарантировать строгое соблюдение инвариантов:
   - Если операция $o_1$ создана каузально раньше $o_2$, то их взаимный порядок никогда не нарушается.
   - Если два узла имеют одинаковые `originLeft` и `originRight`, порядок определяется детерминированным сравнением идентификаторов $\text{ID}$.
   - Отсутствие чередования конкурентно вставленных непрерывных последовательностей (maximal non-interleaving).
4. Реализовать операцию логического удаления (`delete(id)`), выставляющую флаг надгробия (`is_deleted = true`), сохраняя позицию для будущих каузальных ссылок.

## 4. Алгоритмическая спецификация YATA

При вставке узла $N$ между $L = N.\text{origin\_left}$ и $R = N.\text{origin\_right}$:

1. Найти в текущем списке позицию элемента $L$.
2. Сканировать элементы справа от $L$ в поисках точной позиции вставки:
   - Пусть текущий сканируемый элемент $C$.
   - Если $C == R$, остановиться: позиция найдена.
   - Проверить отношение каузальности и истоков $C$:
     - Пусть $O_L = C.\text{origin\_left}$, $O_R = C.\text{origin\_right}$.
     - Если индекс $O_L$ в текущем списке меньше индекса $L$, то $N$ должен идти правее $C$.
     - Если $O_L == L$:
       - Если $O_R == R$, применить детерминированное разрешение по $\text{ID}$: если $N.\text{id} < C.\text{id}$, остановиться перед $C$, иначе двигаться дальше.
       - Если $O_R \neq R$, следовать правилам приоритета поддерева (Fugue tree navigation).
3. Вставить $N$ в найденную позицию.
4. Обновить локальный `StateVector`.

## 5. Граничные случаи и риски
- Конкурентная вставка на пустом документе (когда `origin_left = null` и `origin_right = null`).
- Удаление узла, который служит истоком (`origin`) для еще не доставленной по сети вставки (надгробие должно сохраняться в структуре до полной сборки мусора).
- Сложность поиска: линейный поиск в массиве дает $O(N)$ на операцию. Для 100k+ символов в блоке необходимо использовать двусвязный список с B-Tree индексом или индексное дерево отрезков.
