## 2. Контекст и архитектурная роль
Stateful Collaboration Engine держит активные комнаты редактирования документов непосредственно в оперативной памяти (RAM) для достижения суб-миллисекундного разрешения конфликтов и широковещательной рассылки. 

Чтобы клиенты, редактирующие один и тот же `document_id`, попадали на один и тот же инстанс узла кластера, требуется:
1. Терминация бинарных WebSocket соединений.
2. Sticky-маршрутизация комнат (через Consistent Hashing по `document_id` или Redis Discovery).
3. Менеджер комнат (`RoomManager`), управляющий жизненным циклом комнаты (создание, удержание в памяти при наличии подключений, graceful shutdown и сброс состояния при бездействии).

---

## 3. Цели и задачи
1. Реализовать высокопроизводительный WebSocket-сервер на Go (`gorilla/websocket` или `fasthttp/websocket`) или Rust (`tokio-tungstenite` / `axum`).
2. Реализовать абстракцию `ClientConnection`: чтение бинарных фреймов, буферизованная запись, обработка Heartbeat (Ping/Pong с таймаутом).
3. Спроектировать `Room`:
   - Хранение in-memory экземпляра CRDT документа.
   - Список активных подключений подписчиков.
   - Механизм fan-out рассылки дельт всем участникам, кроме автора правки.
4. Спроектировать `RoomManager`:
   - Реестр активных комнат с потокобезопасным доступом (RWMutex или Actor model).
   - Таймер бездействия (Idle Timeout): если в комнате 0 клиентов в течение 5 минут — сбросить состояние в хранилище и выгрузить из памяти.
5. Обеспечить авторизацию при рукопожатии: валидация Bearer JWT токена в HTTP Upgrade headers / query params.

---

## 4. Архитектурная схема и контракты

```
Client (Alice) ──────┐
                     ├── WebSocket ──> [RoomManager] ──> [Room: doc_123]
Client (Bob)   ──────┘                     │                 ├── In-Memory CRDT
                                           │                 ├── Subscribed Sockets
                                           │                 └── Idle Eviction Timer
                                           ▼
                                   [Auth Middleware]
                                   Validate JWT(user_id, doc_id, role)
```

### 4.1. Конфигурация соединения
- WebSocket Ping/Pong: интервал `30s`, таймаут `10s`.
- Максимальный размер входящего фрейма: `16 МБ` (защита от DoS).
- Буфер исходящих сообщений на клиента: кольцевой буфер на 1 000 сообщений с отсечением медленных клиентов (Slow Consumer Drop).

---

## 5. Граничные случаи и риски
- "Медленные читатели" (Slow Consumers): клиент с плохим интернетом не должен блокировать рассылку остальным 100 участникам комнаты. При переполнении буфера сокет принудительно закрывается с кодом `PolicyViolation`.
- Гонка при одновременном входе первого клиента и выгрузке комнаты: комната должна блокироваться на время инициализации из БД/S3.
