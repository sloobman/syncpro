## 2. Контекст и архитектурная роль
Уникальное преимущество системы SyncPro перед Google Docs или Notion — прозрачная модель версионирования в стиле Git. Авторам и редакторам необходим интуитивно понятный визуальный интерфейс для:
- Навигации по истории документа (Time-Travel).
- Создания и переключения между ветками (`main`, `feature/chapter-2`, `editorial-review`).
- Визуализации графа коммитов (DAG).
- Посимвольного сравнения (Diff) между любыми двумя коммитами или ветками.

---

## 3. Цели и задачи
1. Разработать визуализатор графа коммитов `BranchGraphView`:
   - Отрисовка интерактивного дерева DAG на Canvas или SVG (узлы коммитов, стрелки родителей, цветные линии веток).
   - Подсветка текущего положения `HEAD` и маркеров `Milestone`.
2. Разработать интерактивный скраббер истории `TimeTravelSlider`:
   - Шкала времени с ползунком.
   - Возможность "перемотать" состояние документа на любой коммит в прошлом в режиме `Read-Only Snapshot`.
   - Кнопка "Создать новую ветку из этой точки" (`Fork Branch from Commit`).
3. Разработать компонент посимвольного Diff `CharacterDiffViewer`:
   - Вычисление разницы между состояниями коммита $A$ и коммита $B$.
   - Цветовая индикация: зеленый фон для добавленных символов, красный зачеркнутый для удаленных, серый для неизменных.
   - Фильтр по авторам правок.
4. Разработать диалоговое окно слияния веток `MergeBranchModal`:
   - Выбор исходной и целевой веток.
   - Предпросмотр объединенного результата.
   - Кнопка подтверждения слияния (триггер 3-Way CRDT Merge).

## 5. Граничные случаи и риски
- Зависание UI при Time-Travel по 500-страничному документу: генерация diff и декодирование снапшота должны происходить в изолированном Web Worker, не блокируя главный поток (Main UI Thread).
- Огромное количество коммитов в графе: виртуализация списка коммитов в `BranchGraphView` (рендерить только видимый фрагмент таймлайна).
