## 2. Контекст и архитектурная роль
Обычные веб-редакторы при открытии книги или технической документации объемом 500+ страниц (100 000+ слов) создают десятки тысяч DOM-узлов. Это вызывает:
- Замораживание вкладки браузера (Jank / UI Freezes).
- Потребление оперативной памяти свыше 1-2 ГБ.
- Падение FPS при скролле ниже 15 кадров в секунду.

Для обеспечения целевого показателя (RAM на клиенте $\le 150$ МБ, 60 FPS скролл) необходима **блочно-иерархическая DOM-виртуализация**: в DOM присутствуют только блоки, находящиеся в текущем Viewport пользователя плюс буферная зона (overscan), а остальные блоки представлены легковесными геометрическими спейсерами.

---

## 3. Цели и задачи
1. Разработать движок виртуализации на базе `IntersectionObserver` или кастомного скролл-менеджера.
2. Реализовать расчет высот блоков (`BlockHeightIndex`):
   - Кэширование реальной высоты отредеренных блоков.
   - Эвристическая оценка высоты непросмотренных блоков на основе количества символов и типа блока.
3. Разработать компонент-контейнер `VirtualDocumentList`:
   - Вычисление диапазона видимых блоков: `[firstVisibleIndex, lastVisibleIndex]`.
   - Добавление `padding-top` и `padding-bottom` (или спейсеров) для поддержания честной высоты страницы и нативного поведения системного скроллбара.
4. Обеспечить бесшовную работу навигации по содержанию (Table of Contents) и перехода по якорным ссылкам:
   - При клике на главу 40 мгновенный скролл к плейсхолдеру и ленивая подгрузка блока в DOM.
5. Интеграция с выделением и поиском:
   - Глобальный поиск (`Ctrl + F`) должен искать по CRDT-модели в памяти, а не по DOM, автоматически прокручивая и монтируя найденный блок.

## 4. Схема архитектуры виртуализации

```
[Virtual Document Viewport]
 ┌──────────────────────────────────────────────────┐
 │ Spacer Top: height = 12 400px (блоки 0..140)     │
 ├──────────────────────────────────────────────────┤
 │ [Overscan Top: блоки 141..149]                   │
 │ ──────────────────────────────────────────────── │
 │ [ACTUAL DOM VIEWPORT: блоки 150..170 (VISIBLE)]  │ ──> Активные ProseMirror Nodes
 │ ──────────────────────────────────────────────── │
 │ [Overscan Bottom: блоки 171..179]                │
 ├──────────────────────────────────────────────────┤
 │ Spacer Bottom: height = 48 200px (блоки 180..600)│
 └──────────────────────────────────────────────────┘
```

---

## 5. Граничные случаи и риски
- Дрожание скролла при уточнении высоты (Layout Shift): при первой визуализации блока его расчетная высота может отличаться от фактической. Спейсер должен динамически корректироваться без скачка позиции глаз пользователя.
- Выделение через границы экрана (Cross-viewport drag selection): выделение должно работать на уровне виртуальных координат CRDT, а не нативного выделения окна браузера.
